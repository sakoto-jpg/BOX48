# 阶段 4 前端设计：分团标签页

> 目标：把现在的「一屏卡片流」重做成「分团标签页 + 队列 + 设置」的结构。
> 本阶段只做前端结构与数据隔离，不真正接入新分团（新分团留到阶段 5），
> 但结构必须提前为分团做好准备。

## 一、信息架构

顶部一级标签，从左到右：

| 顺序 | 标签 | 颜色来源 | 内容 |
|---|---|---|---|
| 1 | SNH48 | `#4cb8e8` 浅水蓝 | 该分团的投稿批量下载、公演日历、花名册、统计 |
| 2 | GNZ48 | `#72c13a` 青苹果绿 | 同上（未启用时显示占位说明） |
| 3 | BEJ48 | `#e4007f` 洋红 / 茜粉 | 同上 |
| 4 | CKG48 | `#f5a623` 琥珀黄 / 落日橙黄 | 同上 |
| 5 | CGT48 | `#e23636` 烈焰红 | 同上 |
| 6 | 下载队列 | 中性灰 | 任务引擎、正在下载、排队中、最近完成/失败 |
| 7 | 设置 | 中性灰 | 调度、监听账号、Emby、通知、默认范围、维护工具 |

- 标签顺序与颜色都从后端 `GET /api/groups` 读取（`groups.yaml` 的
  `theme_color`），前端不硬编码，改色只改配置。官方未公布色号，当前是
  按各分团应援色的文字描述取的近似值：SNH 浅水蓝 / BEJ 洋红·茜粉 /
  GNZ 青苹果绿 / CKG 琥珀黄·落日橙黄 / CGT 烈焰红。
- 浅水蓝、青苹果绿这类明度较高的颜色不适合直接填白字，实现时主题色只用于
  标签下划线、徽标、按钮描边与进度条，深色文字仍走中性色，保证可读性。
- 未启用的分团标签仍然显示，但页面内是占位卡片（说明「已完成配置，
  阶段 5 开放」），让扩展进度可见。
- 选中的标签写入 URL hash（`#/snh`、`#/queue`、`#/settings`），
  刷新、收藏、分享都能保持位置。

## 二、各标签页内容

### 分团标签页

1. **该分团统计条**：已入库 / 未入库 / 录播未上传（来自 `/api/uploads/stats`）。
2. **投稿批量下载**：现卡片原样搬入，但所有查询与批量操作都带该分团的
   `group_code`。快捷筛选（TEAM NII/HII/SII/X、预备生、特殊公演）只在
   SNH48 标签内出现，其他分团按各自队伍配置生成。
3. **星梦剧院公演日历**：现卡片搬入，排期只显示该分团。
4. **队伍编排与花名册**：现卡片搬入，只显示该分团的队伍。

拼盘/特别公演（`cast_mode: roster`）在 SNH48 标签下归到「特殊公演」目录，
演职人员固定显示配置里的单个成员，不做剧目匹配。

### 下载队列标签页

1. **任务引擎**：手动输入 BV 号/链接下载的入口（保留现卡片）。
2. **正在下载**：逐分 P 进度、编码、速度、剩余时间。
3. **排队中**：等待中的任务（含批量下载派生的任务）。
4. **最近完成 / 失败**：最近 20 条，失败项提供「重试」按钮。

队列是全局的（下载器是单一串行引擎），所以这里不按分团拆分，但每条任务
标注所属分团，便于辨认。

### 设置标签页

平时不动的配置集中到这里，分组折叠：

| 分组 | 字段 |
|---|---|
| 自动扫描调度 | `scheduler.enabled` / `mode` / `cron_hours` / `interval_hours` |
| 监听账号 | `subscriptions`、`manual_subs` |
| Emby | `server_url` / `api_key` / `library_name`，含「测试连接」 |
| 通知 | `apprise_url`，含「发送测试推送」 |
| 下载范围 | `auto_download_scope` / `manual_download_scope` 默认值 |
| 入库策略（只读） | 编码优先级 AV1 → H.265 → H.264，不可配置 |
| 维护工具 | 同步 wiki 数据、重建剧集元数据、刷新 Emby 素材、查看同步报告 |

「维护工具」按钮直接调用已有接口或工具脚本，代替现在的 SSH 手工执行。

## 三、需要后端配合的改动

1. `GET /api/groups` —— 返回 `[{code, name, theme_color, enabled,
   bilibili_mid, trainee_mode, teams: [...]}]`，前端据此渲染标签与筛选。
2. 现有查询接口加可选 `group_code`：`/api/uploads`、`/api/uploads/stats`、
   `/api/history`、`/api/download_queue`、`/api/schedule_status`。
   - 不传 `group_code` 时保持现状（返回全部），保证前端可灰度切换。
3. `POST /api/maintenance/{action}` —— 触发 wiki 同步 / 元数据重建 / 素材刷新，
   返回任务日志尾部；由后端调用 `tools/` 下的脚本。
4. 队列接口补充「排队中」与「最近完成/失败」两个数组，前端不再需要拼装。

## 四、前端实现方式

- 仍然是单页 + Vue 3 CDN，不引入构建链（保持现在 nginx 直接托管的方式）。
- 把 `frontend/index.html`（约 1000 行）拆成：
  - `index.html`：骨架 + 标签容器
  - `js/api.js`：统一请求封装（超时、错误提示）
  - `js/tabs.js`：标签状态、hash 路由、主题色注入
  - `js/views/*.js`：各标签页组件（group / queue / settings）
  - `js/legacy-cards.js`：现有卡片逻辑迁移过渡用
- 主题色通过容器上的 CSS 变量下发：`--group-color`、`--group-color-soft`，
  激活标签、主按钮、进度条、选中行统一引用这两个变量。
- 移动端：标签横向滚动，卡片改单列。

## 五、实施步骤（每步可单独上线）

| 步骤 | 内容 | 回退方式 |
|---|---|---|
| 4a | 引入标签骨架：现有卡片整体放进「SNH48」标签，「设置」单独成页；新增 `/api/groups` | 保留旧 `index.html.bak`，nginx 指回旧文件 |
| 4b | 数据隔离：接口加 `group_code`，卡片按分团过滤，未启用分团显示占位 | 前端不传 `group_code` 即回到全局视图 |
| 4c | 主题色、hash 路由、快捷键（`1`–`7` 切换）、移动端适配 | 纯样式，无数据影响 |
| 4d | 维护工具按钮接入 `/api/maintenance/*` | 仍可 SSH 手工执行 |

## 六、风险与注意

- 前端是单文件直改，改造前必须留存备份，并在本地用浏览器验证后再覆盖线上。
- 接口加参数要向后兼容（缺省 = 全部），否则会同时打断前端与外部脚本。
- 分团主题色以官方应援色为准，`groups.yaml` 里的初始值需要人工确认一次。
- 队列标签页不做分团拆分，避免「全局串行引擎」与「分团视图」的语义冲突。
- 拼盘/特别公演没有名单来源，统一使用 `roster.yaml` 里「特殊公演」队伍的
  成员（当前是单个占位成员），不为其维护 `performances.yaml`。
